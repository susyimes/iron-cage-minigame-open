# 小游戏与网页版体验审查

本次以相同物理和规则、可完成的完整对局流程、手动画质设置为验收范围。小游戏使用独立 Canvas 菜单以适配微信环境。

| 原有差异 | 修正结果 |
| --- | --- |
| 自动开始单人，HTML 菜单不可见 | 可见首页、玩法说明、设置、暂停、结算与游戏 HUD |
| 抽卡自动选第一张 | 手动三选一，展示增强／使坏目标及卡牌说明 |
| 没有可用的联机入口，连接占位域名 | 原生键盘输入昵称和房间码，接入同一生产 WSS 服务 |
| 按住台面会自动蓄力 | 明确蓄力按钮，瞄准手势独立，滑出／触摸中断取消 |
| 跨手指或跨菜单残留输入 | 按触点分配操作；菜单切换、选卡、换局、后台均清理残留 |
| 背景音乐读取失败 | 公开版使用合成环境声，未复制旧音乐 |
| 切回前台未同步 | hide/show 更新可见性，重置输入并触发已有联机同步 |
| 原型替换破坏 Canvas 尺寸 setter | 保留原生原型和尺寸访问器，只补 DOM 兼容方法，修复画面裁切 |
| 快速退出连接仍可能迟到打开 | 关闭中的 socket 忽略迟到 open 并再次关闭底层任务 |

两端共享八球规则、单人犯规复位、换手默认水平杆、各自瞄准及双方确认原房重开。画质三档均持久化、手动调整，无自动降档。

## 验证

- `test:minigame` 覆盖按住蓄力、多指隔离、取消、切后台、菜单阻挡、原生画布 setter、配置域名、已移除音乐的访问隔离、输入校验、手动抽卡、重开状态与安全区按钮布局。
- `test:online` 验证服务器规则、房间、同步和独立瞄准／重开协议。
- 浏览器同一小游戏 UI 与网页进入同房，实际点击蓄力出杆；网页收到相同第 2 杆、100 分和 14 球，退出后小游戏提示对手离开并禁止失效重开。
- 微信开发者工具实际编译和截图确认完整首页，修复前后的绘制缓冲区由错误的 `844×390` 改为与高画质目标一致的 `1266×585`。
- IDE 自动触控接口返回 `canvas not found`，因此未将浏览器触控验证冒充微信原生触控或真机验证。发布前应扫码检查原生键盘、双指操作、听感、socket 合法域名和不同手机帧率。

浏览器开发预览使用同一 `MiniUi` 和触控绑定，但提供的是浏览器宿主；微信运行时兼容层另有回归检查。开发版上传成功不等于审核已提交或审核通过。

API 形状依据微信官方 [小游戏类型定义](https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/types/wx/lib.wx.api.d.ts)。
